# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A small, dependency-free tool for exploring Craiova's residential parking auctions (`parcari-ticketing.primariacraiova.ro`). Two pieces:

- `fetch_blocuri.py` scrapes one JSON file per building ("bloc") into `blocuri/<id>.json`.
- `export_shapefile.py` writes two zipped WGS84 polygon shapefiles to `shapefiles/`, copying the Roermond examples there (stdlib only): `craiova_<date>_4326.zip` with one record per parking spot, inactive ones left out (29 columns; ones with no Craiova data are empty/null; `area_id`/`park_code` are the lot id/name, `shape_id` the spot number), and `scanplanner_craiova_<date>.zip` with one record per neighbourhood zone and its total `spot_count`. OSM only has points for Craiova's neighbourhoods (cached in `neighbourhoods.json` from Overpass; delete it to refetch), so each lot goes to the nearest point and a zone is the convex hull of its lots clipped to that point's Voronoi cell. The zone name also goes into the spots file's `neighborh`/`roof_id`, as in Roermond.
- `serve.py` serves the viewer (static files plus a refetch endpoint, see below).
- `build_site.py` writes a static copy for hosting (Cloudflare Pages) into `site/`: `index.html` plus `data.json`, all blocs in one file with each lot stored once (`{"blocs": [...], "lots": {id: lot}}`, a bloc's `parking_lots` become `[[lot id, distance], ...]`, `fetched` is the file's mtime in ms). About 22 MB, ~3 MB compressed; Cloudflare's per-file limit is 25 MiB.
- `index.html` is a single-file viewer (vanilla JS + inline SVG, no build step) that loads every file in `blocuri/` and draws buildings, parking lots and spots on a pannable/zoomable map, colored by auction registration count.

There is no package manager, build, lint or test setup.

## Commands

```sh
# Fetch data (default id range 5050–8521, inclusive). Existing files are skipped, so re-running resumes.
python3 fetch_blocuri.py [start_id] [end_id]

# Export lots and neighbourhood zones as shapefiles into shapefiles/ (or out_dir)
python3 export_shapefile.py [out_dir]

# View: serve over HTTP (see below), then open http://localhost:8000
python3 serve.py [port]

# Static site for hosting into site/ (or out_dir), then deploy that folder, e.g.
# npx wrangler pages deploy site --project-name <name>, or upload it in the Cloudflare dashboard
python3 build_site.py [out_dir]
```

## Things that aren't obvious from a single file

- **Auth:** the fetcher first regex-parses the `-b '...'` cookie string (accessToken/refreshToken) out of `sample_curl.sh`, if that file exists. On HTTP 401 it calls `api/person/refresh` to rotate the access token. If there are no cookies or the refresh fails, it logs in with `POST api/person/login`, JSON body `{"EMAIL": ..., "password": ...}` (401 = wrong password, 403 = unknown email), and the server sets the token cookies. Credentials come from `PARCARI_EMAIL` / `PARCARI_PASSWORD`, or a prompt when stdin is a TTY (the fetcher only; `serve.py` never prompts, the viewer asks instead, see below). They're kept only in memory; `login()` leaves the failure reason in `login_error`. `sample_curl.sh` holds live session tokens; don't print them or copy them elsewhere.
- **Endpoint:** `GET api/immobile/{id}?distance_to_parking_lot=30`. A response is saved only if it's a dict containing `parking_lots`; other ids are reported as missing, grouped by HTTP status. The script sleeps 0.2s between requests and backs off on 429/5xx.
- **The viewer first tries `data.json`** (only present in a `build_site.py` copy). If it loads, `staticSite` is set and the refetch button is hidden. Otherwise it **relies on the server's directory listing.** `serve.py` subclasses `SimpleHTTPRequestHandler`, so it provides one, and so does `python3 -m http.server`. `loadAll()` fetches `blocuri/`, parses the HTML index for `*.json` links, then loads them with 8 concurrent workers. Another static server without auto-index (or opening via `file://`) won't work.
- **Refetching one bloc:** the bloc details panel has a "Refetch this bloc" button that sends `POST api/refetch/<id>` to `serve.py`. The server calls `fetch_blocuri.fetch_bloc()` and `save()` (an atomic write over `blocuri/<id>.json`; file names equal building ids) and returns the bloc JSON. The browser can't call the city API itself because of CORS and the cookies. `serve.py` binds to 127.0.0.1 only, sends `Cache-Control: no-cache` so a reload never shows a stale cached file, serializes API calls with a lock, and sets `fetch_blocuri.interactive = False` before its startup login, so nothing blocks on a terminal prompt. When a refetch gets a 401 (no session, and the env credentials are missing or wrong), the viewer opens its login `<dialog>` (`askLogin()`), posts `{"email", "password"}` to `POST api/login`, which replaces `fetch_blocuri.credentials` and calls `login()` (bad credentials are cleared again), then retries the refetch once. That endpoint requires `Content-Type: application/json` so another site's page can't post to it without a CORS preflight, which fails. Under plain `http.server` the POST gets a 501, and the viewer says to use `serve.py`. In the viewer, `updateBloc()` removes the old features of the building and of every lot it was or is now near (`removeFeature`/`removeLot`), re-adds them from the new data (`addBuilding`/`addLot`), and keeps other blocs' entries in `lot.distances`.
- **Data shape:** each file is a building (`id`, `name`, `street`, `house_number`, `full_name`, `geometry` Polygon in lon/lat, `waitlist`, `parking_lots[]`). Each lot has `distance` (to this building), `geometry`, `auctions[]` and `residence_parking_spots[]`. Auction `items[]` link to spots by `id_res_parking_spot` and carry `registration_count`, prices and `current_bid`. Only `auctions[0]` is used.
- **Deduplication:** neighbouring buildings share lots, and the loader also tolerates the same building appearing in more than one file. The viewer keeps one building per `id` and one lot per `id`, collecting `[label, distance, bloc id]` per building on `lot.distances` and keeping the reverse link as `building.nearLots`. Each file's `Last-Modified` is stored as `fetched` (shown as "Data from"); when copies of a shared lot differ, the newest file's copy wins, so a refetched lot isn't shadowed by stale copies in neighbours' files.
- **Rendering is on a `<canvas>`, not SVG.** The SVG version (~100k elements for ~28k spots) lagged on every pan. lon/lat is projected to Web Mercator scaled to meters at the center latitude (`S` = meters per whole mercator world), so raster tiles line up exactly. `SOURCES` holds the backgrounds chosen in the settings dialog (Map / Satellite / None, saved to `localStorage` as `background`): OpenStreetMap (`tile.openstreetmap.org`, max z19) and Esri World Imagery (`server.arcgisonline.com/.../World_Imagery/MapServer/tile/{z}/{y}/{x}` — note y before x; Craiova only has imagery up to z18, z19 returns a "Map data not yet available" placeholder, so its `maxZoom` is 18 and closer zooms stretch z18). Tiles are drawn first by `drawTiles`; each source has its own attribution overlay (required) and alpha, and only OSM is inverted in dark mode. `view` holds the top-left world point and pixels-per-meter. Tiles from both sources share a 400-entry LRU keyed `src/z/x/y`; a missing tile is stood in for by a loaded lower-zoom ancestor, and dark-mode OSM uses a once-per-tile inverted copy (`ctx.filter` per frame was ~4× slower). Each polygon becomes a "feature" (projected ring, bbox, `Path2D`), bucketed into 500 m chunks that each hold one combined `Path2D` per style layer (lot, building, one per spot color, spot strokes, handicap dashes). Each feature remembers its `layers` and chunk `key`; a chunk's combined paths are built lazily on the first render that shows it, and reset to `null` whenever a feature is added or removed. A frame paints only the visible chunks, layer by layer, then overlays (near lots, selected bloc, hovered/selected spot) and labels. Redraws go through `schedule()` (one per animation frame). Labels are skipped when the visible width is over 400 m (spots and lots) or 2000 m (buildings). Clicks and hover tooltips use point-in-polygon hit testing over the chunks: spots first, then buildings, then lots. Input is pointer events on the canvas (`touch-action: none`, pointer capture): one pointer pans, two pinch-zoom around their midpoint (`regrip()` re-pins the world point under the grip whenever a finger is added or lifted), a press that moves under 4 px (10 px for touch) is a click, and a second one within 350 ms zooms in ×2 (`zoomAt`). Touch has no hover, so a tap leaves its tooltip up until the next tap or drag. The map's corner buttons zoom in/out, fit everything, and toggle "Show my location" (`watchPosition`, drawn as `me`; needs HTTPS or localhost). Below 1100 px the map sits above the lists, so `zoomTo` scrolls it into view; below 700 px the canvas is 65vh so the page can still be scrolled outside it, details come before the legend, and inputs are 16px (iOS zooms in on smaller ones). Line widths and dashes are divided by the scale so they stay constant in screen pixels.
- With ~3.5k files the point count is large, so bounds are computed with loops (`Math.min(...arr)` overflows the stack).
- Theme colors are CSS variables on `:root`. Dark values are defined twice: under `:root[data-theme="dark"]`, and under `prefers-color-scheme: dark` for `:root:not([data-theme="light"])`. The Dark mode switch (in the settings `<dialog>` opened by the header gear button, next to the OpenStreetMap switch) sets `data-theme` and saves it to `localStorage` (applied by an inline `<head>` script before first paint); with no saved choice the system preference wins. Use `isDark()` rather than the media query. The canvas can't use CSS variables, so `readColors()` copies them into `C`, re-read on the `themechange` window event. Registration buckets are `--c0`…`--c3` (0, 1, 2, 3+) and `--none` (spot not in auction).
